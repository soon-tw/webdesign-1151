UI 與 UX 差在哪

課程進度：Part 1｜設計是一種溝通本頁主題：UI／UX 定義

用「去餐廳吃飯」來想：菜單長相是 UI，從訂位到買單的整段經驗是 UX。

UI：看得到、摸得到的

  • 畫面上的按鈕、字型、顏色、間距、圖示
  • 像菜單的排版、餐具的樣子
  • 可以截圖、可以交給工程師切版
  • 好壞多半一眼能看出

UX：使用的過程與感受

  • 找得到、看得懂、做得完、不出錯、想再來
  • 像訂位順不順、等多久、上菜錯了怎麼辦
  • 要觀察真人使用才知道
  • 由「使用的人」說了算，不是設計師

常見誤解：UI 漂亮不等於 UX 好；UX 不是多加動畫，而是少讓使用者卡住。

這頁記住：UI 是看得到的，UX 是用起來的感覺。

設計師的職責

課程進度：Part 1｜設計是一種溝通本頁主題：角色與目標

做出來的東西，要幫客戶達成目標。

  • 客戶有「想透過網站完成的事」；看不懂需求，再帥的網站也沒意義。
  • 設計＝與使用者對話：網站用文字、圖像傳達，使用者看懂才會行動。
  • 設計不是照稿畫圖，要主動問「為什麼要這樣排」，和企劃、工程師平等討論。
  • 設計的根本是解決問題，包含使用者說不出口的不便。

討論時的三個動作

問　「為什麼會做成這樣？」（不要問「為什麼這麼難用」）

說　「如果目的是 X，這樣排會更好。」

驗　先畫粗稿當場確認，再細修。

這頁記住：設計師不是美工，是和團隊一起解決問題的人。

設計法則：格式塔理論 Gestalt Theory｜距離

課程進度：Part 1｜設計是一種溝通本頁主題：近接性（Proximity）

靠得近，就被看成同一群。

  • 人眼會自動把靠近的東西歸成一組，這是格式塔理論 Gestalt Theory 的近接性（Proximity）原則。
  • 間距一致 → 一整片；多一個間距不同 → 被當成「例外」。
  • 互動時更重要：✕ 放在哪個框的角落，決定使用者預期「關的是誰」。
  • 圖與說明要靠在一起，別讓人猜「這張圖在說哪一段」。

想強調列表中的某一項，不要只改它的圖示或留白規則。

這頁記住：距離就是關係：近的屬於同一組。

設計法則：格式塔理論 Gestalt Theory｜封閉與連續

課程進度：Part 1｜設計是一種溝通本頁主題：封閉（Closure）與連續（Continuity）

可以點的東西，要圈出來。

  • 網頁內容不只可看，還可操作；可點選的元素最好用封閉（Closure）形狀（框、底色、按鈕）標示。
  • 用線劃區塊很有效，但線兩側要留白，內容區會變窄。
  • 手機的標籤列、導覽列要明確圈出主要內容，避免點錯。
  • 對齊讓視線連續（Continuity），不規則排列會讓人疲於找下一個。

版面要說得出理由

課程進度：Part 1｜設計是一種溝通本頁主題：設計依據

被問「為什麼這樣排？」，不能只說「我覺得」。

1目的這一頁要讓人做什麼？
2使用者誰、在什麼情境？第一眼要看什麼？
3原則用了距離（Proximity）、相似（Similarity）、封閉（Closure）、對比（Contrast）的哪一條？
4驗證移開視線再看，第一眼對不對？

有根據的回答

  • 「出發時間放最大，因為使用者在趕車，第一眼要先看時間。」
  • 「價格縮小變灰，因為它是次要資訊。」

沒根據的回答

  • 「我覺得這樣比較好看。」
  • 「別的網站也這樣。」
這頁記住：原則不是用來說服老闆，是讓討論有共同標準。

課程進度：Part 1｜設計是一種溝通本頁主題：媒介差異

紙本的好版面，搬到網頁常常就完蛋。

面向紙本網頁
範圍尺寸固定，看得到頭尾長度不定，看不到終點

跳讀與集中注意力

課程進度：Part 2｜視覺實踐本頁主題：閱讀行為

網頁看不到終點，使用者會先掃一遍再挑著看。

  • 紙本有固定範圍，網頁長度不定；使用者習慣跳讀。
  • 單調、規則一致的版型最適合長文章；不規則編排會讓人找不到段落。
  • 內容精簡到一眼讀完時，才適合大膽變化版型。
  • 先看內容的「量」與「質」，再決定版型。

讓跳讀好用的長文結構

標題　每段一個小標，說明這段講什麼

段首　先給結論，再給細節

重點　粗體標關鍵詞，每段不超過一處

間距　圖與文字的距離、位置統一

摘要　列表先給簡述，有興趣再點「閱讀全文」

這頁記住：長文要規則，短文才有餘裕玩變化。

扁平化設計的原則

課程進度：Part 2｜視覺實踐本頁主題：扁平化

扁平不是「看起來平」，是簡化人與機器的關係。

  • 主角是內容，介面是配角；按鈕不要比內容更搶眼。
  • 但「可以按」的線索不能丟：觸控世代不期待按下去會凹，習慣電腦的族群仍需要提示。
  • 連結不需要做成按鈕，底線就是最好的提示。
  • 是否扁平，視使用者而定：目標族群熟不熟悉觸控介面？

網頁字型

課程進度：Part 2｜視覺實踐本頁主題：字型選擇

字型先要好讀，再談好看。

  • 網頁字型（Web Font）讓每個人看到同一種字；Google Fonts 免費、開源、可商用。
  • Noto Sans TC、Noto Serif TC 含繁體中文，且有多種字重。
  • 內文別用太有個性的字型，使用者會不習慣、難閱讀。
  • 中文字型檔很大，要做字型子集（本課簡報就是這樣離線的）。

字級、行距與圖片文字

課程進度：Part 2｜視覺實踐本頁主題：可讀性

字要夠大、行要夠鬆，而且不要把字做成圖。

  • 內文至少 16px；手機輸入框小於 16px，iOS 會自動放大畫面。
  • 行高 1.5–1.8，中文比英文需要更鬆；每行約 25–35 字最舒服。
  • 單位用 rem／em，使用者調大字級時，行距會跟著變。
  • 文字做成圖片：Retina 會糊、手機縮小後看不清、改字要開設計軟體。
CSS 與 Tailwind 的對照CSS
.article {
  font-size: 1rem;      // 16px
  line-height: 1.75;
  max-width: 35em;      // 約 35 字
}

<p class="text-base leading-7 max-w-[35em]">
這頁記住：可讀性是數字，不是感覺。

rem根元素字級（預設 16px）字級、間距、元件尺寸全站一致、可縮放要換算（1rem＝16px）
em目前元素的字級行距、按鈕內距、圖示跟著該元件放大縮小巢狀會連乘，易失控
%父元素的尺寸寬度、欄位比例自動適應容器父層沒設高度就無效
vw／vh視窗寬／高滿版區塊、流體字級隨視窗等比縮放手機網址列使 vh 失準
ch數字「0」的寬度文章行寬（如 65ch）依字數控制行長中文字寬不同，只能估

口訣：字與間距用 rem，細線用 px，元件內部比例用 em，版面寬度用 % 或 vw。Tailwind 的 text-base、p-4 底層就是 rem。
