標頭 Headers：信封上的備註

課程進度：A–B1｜開場與 API 基礎本頁主題：HTTP 標頭

標頭是「名稱: 值」的成對資訊，說明這次請求或回應的條件。

請求常見標頭

  • Accept：我想收什麼格式（例：application/json）
  • Content-Type：我送出的內容是什麼格式
  • Authorization：通行證（token、金鑰）

回應常見標頭

  • Content-Type：回來的是 JSON 還是網頁
  • Access-Control-Allow-Origin：瀏覽器可不可以讀（CORS）
  • Retry-After：被限流時，多久後再試

實測 YouBike（2026-11-14）：回應有 Access-Control-Allow-Origin: *，所以瀏覽器裡的程式讀得到。

這頁記住：狀態碼說結果，標頭說條件。

13/71

等資料時，畫面不能停住

課程進度：A–B1｜開場與 API 基礎本頁主題：同步與非同步

請求要花時間，程式不能卡在原地等。

  • 像點餐拿號碼牌：先去做別的事，餐好了再叫你。
  • await 的意思是「等這一步好了再往下」，但整個畫面仍可操作。
  • 重點：fetch 遇到 404、500 不會自動當成錯誤，要自己檢查 res.ok。
  • 等待中顯示 Loading，就是 11/12 學的狀態設計。
fetch 概念示範（下週改用 Angular HttpClient）JS
async function load(url) {
  const res = await fetch(url); // 等回應
  if (!res.ok) {         // 404、500 自己擋
    throw new Error(`HTTP ${res.status}`);
  }
  return await res.json(); // 轉成資料
}
這頁記住：非同步＝先做別的事，資料到了再更新畫面。

JSON 的語法規則

課程進度：B1＋｜JSON 與 fetch本頁主題：JSON 語法

JSON 長得像 JavaScript 物件，但規則更嚴格：差一個符號就讀不進來。

不好JavaScript 物件可以，JSON 不行

  • 屬性名不加引號：{ name: '炒飯' }
  • 單引號：'炒飯'
  • 最後一項後面多一個逗號
  • 註解 // 備註
  • undefined、函式

好JSON 的規定

  • 屬性名一定加雙引號：{ "name": "炒飯" }
  • 字串用雙引號
  • 最後一項後面不能有逗號
  • 不能寫註解
  • 值只有：字串、數字、true／false、null、物件、陣列

看不出哪裡錯？把內容貼到 VS Code 存成 .json 檔，錯的地方會出現紅色波浪線。

這頁記住：JSON：雙引號、不能多逗號、不能註解。

JSON 與 JavaScript 互換

課程進度：B1＋｜JSON 與 fetch本頁主題：JSON.parse

收到的是一串文字；要先轉成 JavaScript 的物件或陣列才能用。

  • JSON.parse(文字)：文字 → 物件／陣列。
  • JSON.stringify(物件)：物件 → 文字（送出、存檔時用）。
  • 收到的不是 JSON（例如錯誤頁 HTML）：parse 會丟錯誤。
  • 右邊是 Chrome 實際的錯誤訊息。
文字與物件互換JS
const text = '{"name":"炒飯","price":60}';
const meal = JSON.parse(text);
meal.price;            // 60（數字）

JSON.stringify({ name: '水餃' });
// '{"name":"水餃"}'
parse 到 HTML 時（實測）OUTPUT
JSON.parse('<html>')
// SyntaxError: Unexpected token '<',
//   "<html>" is not valid JSON
這頁記住：文字要 parse 才能用；看到 Unexpected token < 就是拿到 HTML。

同步與非同步：差在「要不要等」

課程進度：B1＋｜JSON 與 fetch本頁主題：同步／非同步

Promise、async、await 都是為了「非同步」而生，先把這兩個詞分清楚。

同步：一件做完，才做下一件

  • 像超商排隊結帳：前一位沒結完，後面全部等。
  • 適合馬上有結果的事：加減乘除、字串處理、陣列排序與篩選。
  • 缺點：若其中一步很慢，整個畫面跟著卡住、按鈕按不動。

非同步：先去做別的，好了再通知

  • 像點餐拿號碼牌：先去找座位，餐好了再叫號。
  • 適合要等外部的事：fetch 呼叫 API、setTimeout 計時、讀取檔案、等使用者點擊。
  • 好處：等待期間畫面照常可以捲、可以點。

判斷口訣：結果要「等別人」給（網路、計時器、使用者）→ 非同步，就輪到 Promise 與 async／await 上場。

這頁記住：同步＝排隊等；非同步＝拿號碼牌，先做別的。

async 函式

課程進度：B1＋｜JSON 與 fetch本頁主題：async／await

await 只能寫在 async 函式裡；把取資料包成一個函式，到處都能呼叫。

  • 函式前面加 async，裡面才能用 await。
  • async 函式本身也回傳 Promise。
  • 呼叫它的地方也要 await，或接 .then()。
  • Console 可以直接 await，是方便測試的特例。
包成函式JS
async function loadStations() {
  const res = await fetch(url);
  const data = await res.json();
  // 只留有車的站
  return data.filter((s) =>
    s.available_rent_bikes > 0);
}

const list = await loadStations();
console.log(list.length);
這頁記住：async 函式裡才能 await。

fetch 的兩種失敗

課程進度：B1＋｜JSON 與 fetch本頁主題：兩種失敗

這是 fetch 最容易誤會的地方：404、500 不算失敗。

  • 伺服器有回應（404、500）：fetch 照樣成功，要看 res.ok。
  • 實測：錯誤網址回來 status: 404, ok: false，沒有任何錯誤。
  • 完全沒有回應（斷網、網域不存在、CORS）：fetch 丟出錯誤。
  • 實測斷網：TypeError: Failed to fetch。
這頁記住：有回應看 res.ok；沒回應用 try／catch。

22/71

完整寫法：檢查 res.ok＋try／catch

課程進度：B1＋｜JSON 與 fetch本頁主題：錯誤處理

兩種失敗都處理，畫面才能說出正確的訊息（第 33 頁的對照表）。

loadStations（完整版）JS
async function loadStations() {
  try {
    const res = await fetch(url);
    if (!res.ok) throw new Error(`讀取失敗（${res.status}）`); // 404、500……
    return await res.json();
  } catch (err) {
    console.error(err); // 斷網、CORS，或上面丟出的錯誤
    return [];
  }
}

下週的 HttpClient 會自動把 404、500 當成錯誤，並提供 err.status，這一頁的判斷就不用自己寫了。

這頁記住：!res.ok 自己丟錯誤；catch 接住所有失敗。

狀態碼白話常見原因怎麼修
400 Bad Request看不懂你在說什麼JSON 壞掉、缺必要參數對照文件檢查送出的內容

用戶端錯誤（二）與兩組易混淆

再認識四個，並分清最常搞混的兩組。

  • 405 方法不對：只能 GET 的網址你用了 POST。
  • 409 衝突：重複新增、資料已被別人改過。
  • 422 內容不合規則：格式對，但 Email 不像 Email。
  • 429 太頻繁：被限流了，等一下再試。

401 vs 403

  • 401：不知道你是誰 → 去登入
  • 403：知道你是誰，但你不行 → 登入也沒用

404 vs 200 空陣列

  • /posts/9999 → 404：這一筆不存在
  • /posts?userId=999 → 200 與 []：查詢成功，只是沒有符合的

兩個例子皆為 2026-11-14 對 JSONPlaceholder 實測。

這頁記住：「找不到這筆」是 404；「條件查無結果」通常是 200 加空陣列。

伺服器錯誤：500、502、503、504

5 開頭不是你寫錯，但你的畫面要能好好處理。

狀態碼白話要不要重試
500 Internal Server Error伺服器內部壞了可以，但別一直狂按

課程進度：B2–B3｜狀態碼、錯誤訊息與 RESTful本頁主題：REST 是什麼

REST 是設計 API 的慣例，不是套件，也不是檔案格式。

  • 資源（名詞）：網址代表一種東西，例 /posts 文章。

GET /posts?userId=1 → 「列出 1 號使用者的文章」

這頁記住：網址放名詞，動作交給方法，結果交給狀態碼。
