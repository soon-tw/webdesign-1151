04/52

為什麼需要 TypeScript

課程進度：01 / 07 開場與型別基礎本頁語法／概念：型別安全

JavaScript 只有在「跑起來」之後才會發現用錯；TypeScript 在打字時就提醒你。

  • 把 "80"（字串）當數字算，JS 會給你 "808080" 這種怪結果。
  • TypeScript 是「加上型別的 JavaScript」：寫法幾乎一樣，多了型別描述。
  • 型別錯誤在編輯器裡就畫紅線，不用等執行；右邊就是同一段程式的對照。
TypeScript
export class ProductService {
  total(price: number, n: number): number {
    return price * n;
  }
}
new ProductService().total(80, 3);   // 240
JavaScript
export class ProductService {
  total(price, n) {
    return price * n;
  }
}
new ProductService().total(80, 3);   // 240

同一段邏輯，兩欄只差型別註解。TS 的 total('80', 3) 在打字時就紅字；JS 不報錯，得到 '808080'。

這頁記住：TypeScript＝JavaScript ＋ 型別檢查；錯在打字時就發現。

07/52

型別註記：冒號後面是什麼

課程進度：01 / 07 開場與型別基礎本頁語法／概念：型別註記

型別註記就是在變數後面加「冒號 ＋ 型別」。

  • let price: number = 50;：price 只能是數字。
  • 寫成 price = "50" 會立刻出現型別錯誤。
  • 冒號後面是「這個值是什麼型別」，不是「值」。
  • 常見基本型別：number、string、boolean。
TypeScript本頁重點
// ProductService 的方法
priceOf(): number {
  let price: number = 50;
  price = 80;      // OK
  // price = '50'; // 型別錯誤
  return price;
}
圖解 X｜型別註記與推論
型別註記與推論怎麼選

先靠推論

  • 有初始值就讓 TS 自己判斷
  • let price = 50 → number

需要時才註記

  • 函式參數、回傳值最常需要
  • let price: number = 50

好處

  • 改錯型別時當場紅字
  • 讀程式的人一眼看懂
這頁記住：冒號後面寫型別：let price: number = 50;

型別推論：能推就不必寫

課程進度：01 / 07 開場與型別基礎本頁語法／概念：型別推論

大部分時候你根本不用寫型別——TS 會從初始值推論出來。

  • let price = 50; TS 推論 price 是 number。
  • const name = '炒飯'; 推論為 string。
  • 推論之後就不能再塞別的型別：price = '50' 會報錯。
  • 把滑鼠移到變數上，編輯器會顯示它推論出的型別。
TypeScript本頁重點
// ProductService 的方法
firstPrice(): number {
  let price = 50;       // 推論 number
  // price = '50';      // 型別錯誤
  const name = '炒飯';  // 推論 string
  return price;
}
圖解 X｜型別註記與推論
型別註記與推論怎麼選

先靠推論

  • 有初始值就讓 TS 自己判斷
  • let price = 50 → number

需要時才註記

  • 函式參數、回傳值最常需要
  • let price: number = 50

好處

  • 改錯型別時當場紅字
  • 讀程式的人一眼看懂
這頁記住：有初始值，TS 自己就知道型別；能推就不必寫。

函式型別：參數與回傳契約

課程進度：01 / 07 開場與型別基礎本頁語法／概念：參數、回傳

函式也能標型別：輸入（參數）與輸出（回傳值）都要說清楚。

  • 函式契約清楚，別人（和 AI）就知道怎麼用。

total(price: number, count: number): number {
  return price * count;
}

// 呼叫：new ProductService().total(80, 3) → 240
這頁記住：函式的輸入口與輸出口都標型別，呼叫就不會錯。

12/52

TS vs JS 並排：計價函式

課程進度：01 / 07 開場與型別基礎本頁語法／概念：對照

同一段計價函式，寫成 TS 與 JS 差在哪？

  • TS：參數與回傳都標型別，呼叫錯立刻紅字。
  • JS：寫法一樣，但錯要等執行、看到 NaN 才知道。
  • 型別註記在編譯後會被移除，執行時幾乎沒有成本。
TypeScript
export class ProductService {
  finalPrice(p: number, off: number): number {
    return Math.round(p * off);
  }
}
JavaScript
export class ProductService {
  finalPrice(p, off) {
    return Math.round(p * off);
  }
}

呼叫 finalPrice(80, 0.9) 得到 72；改傳 '80' 時 TS 當場紅字，JS 不報錯、得到 NaN。

這頁記住：同一段邏輯，TS 多寫型別、換到當場的安全性。

type 別名與 interface 比較

課程進度：02 / 07 物件型別、interface 與 JSON本頁語法／概念：type、比較

interface 與 type 都能描述物件，差別在能不能組合。

  • interface Product { ... } 與 type Product = { ... } 幾乎等價。

  • 本課：描述物件用 interface；需要組合時用 type。
TypeScript本頁重點

  id: number; name: string; price: number;

16/52

選用屬性 ? 與 readonly

課程進度：02 / 07 物件型別、interface 與 JSON本頁語法／概念：optional、readonly

兩個常用修飾：? 表示可有可無，readonly 表示不能改。

  • discount?: number 表示這個欄位可以不存在。
  • readonly name: string 表示建立後不能改。
  • 取用前要記得：可有可無的欄位可能是 undefined。
  • id、price 這種會變的欄位就不加 readonly。
TypeScript本頁重點
// 頂層宣告
interface Product {
  id: number;
  readonly name: string;
  price: number;
  discount?: number;   // 可有可無
}

const p: Product = { id: 1, name: '炒飯', price: 80 };
// p.name = '拉麵';  // 錯誤：readonly
這頁記住：? 可有可無；readonly 不能改。

JSON 是什麼：物件與文字之間的橋

課程進度：02 / 07 物件型別、interface 與 JSON本頁語法／概念：JSON 格式

物件是程式裡的東西；JSON 是它的文字版，用來存檔與傳輸。

  • JSON 是純文字格式，不是 JavaScript：鍵名一定要用雙引號。

  • 值只有 6 種：字串、數字、布林、null、陣列、物件。

// product.json：JSON 是純文字，鍵名要雙引號

  "id": 1,
  "name": "炒飯",
  "price": 80,
  "tags": ["主食", "特價"]
}

JSON 的語法規則與 6 種值

  • 沒有 undefined、函式、Date

鍵名一定要雙引號

JSON 與 TypeScript 型別對應

課程進度：02 / 07 物件型別、interface 與 JSON本頁語法／概念：JSON ↔ 型別

JSON.parse 的結果是 any——不標型別，就等於關掉檢查。

  • JSON 的 6 種值對到 TS：string、number、boolean、null、T[]、物件。
  • 用 interface Product 描述 JSON 的形狀，取用欄位才有提示。
  • as Product[] 只是「斷言」，TS 不會真的檢查內容。
TypeScript本頁重點
// JSON.parse 回傳 any：型別要自己標
const one: Product = JSON.parse(text);
const raw = JSON.parse(text) as Product[];

// 物件 → 文字：存檔、送出都要它
const json: string = JSON.stringify(one);
圖解 AP｜JSON.parse 的型別落差
JSON.parse 之後怎麼保住型別

parse 回傳 any

  • any 等於關掉檢查
  • 打錯欄位名不會有紅字

標上 interface

  • const p: Product = JSON.parse(text)
  • 取用欄位時就有提示

as 只是斷言

  • as Product[] 不檢查內容
  • 要真驗證得自己寫檢查
這頁記住：JSON.parse 回傳 any；標上型別（或自己驗證）才有保護。

交叉型別：把兩個形狀疊起來

課程進度：03 / 07 聯合、交叉與型別收窄本頁語法／概念：intersection

交叉型別用 & 把兩個形狀疊成一個。

  • Product & { finalPrice: number } 同時具備兩邊的欄位。
  • 常用在「原資料 ＋ 額外計算欄位」，例如折扣後價格。
  • 產生的新物件必須同時滿足兩個形狀。
  • 搭配展開運算子 { ...p, finalPrice } 最常見。

type Product = {
  id: number; name: string; price: number;
};
type Discounted = Product & { finalPrice: number };

const d: Discounted = { id: 1, name: '炒飯', price: 80, finalPrice: 72 };

型別收窄：typeof 分流

type StockStatus =
  | { kind: 'in'; qty: number }

status(p: Product): StockStatus {

// 練習 5：泛型查詢 firstBy
firstBy<T, K extends keyof T>(items: T[], key: K, value: T[K]): T | undefined {

}

// 練習 6：模擬 API 取得商品
async loadDeals(): Promise<string[]> {
  try {
    const res = await fetch('/api/products');
    if (!res.ok) throw new Error('HTTP 錯誤');
    const body: ApiResponse<Product[]> = await res.json();
