07/62

從上週的 JS 搬過來

課程進度：01 / 06 開場與工具本頁語法／概念：JS 與框架

上週你用 textContent 改畫面；這週同一件事，換 Angular 幫你記住。

  • 上週：抓元素 → 改 textContent → 自己記得哪裡要更新。
  • 這週：宣告資料 → 模板寫 {{ }} → 資料變了畫面自己變。
  • 事件、資料、畫面三站沒變，變的是「誰負責更新」。
  • 你不用再 querySelector，也不用記得同步幾個地方。
上週 JavaScript
let count = 0;
btn.onclick = () => {
  count = count + 1;
  num.textContent = count;
};
這週 Angular
count = signal(0);

add() {
  this.count.set(this.count() + 1);
}
這頁記住：框架不是新語言，是幫你把「更新畫面」這件事接走。

08/62

三個檔案各管一件事

課程進度：01 / 06 開場與工具本頁語法／概念：檔案分工

一個元件通常就三個檔案，各管一件事。

  • app.ts：資料與行為（signal、方法）。
  • app.html：畫面結構（標籤、{{ }}、@if、@for）。
  • app.css：外觀（顏色、間距、字級）。
  • main.ts 只負責啟動 App；前面接好後，本週不用再改。
HTML模板
<!-- app.html：畫面結構 -->
<h1>{{ shopName }}</h1>
<p>{{ price }} 元</p>
CSS樣式
/* app.css：外觀 */
h1 { font-size: 40px; }
.price { color: #2f5d50; }
TypeScript資料與方法
// app.ts：資料與方法
export class App {
  shopName = '晚班補給站';
  price = 80;
}
這頁記住：要改字找 html、改行為找 ts、改外觀找 css。

12/62

元件的三張工作單

課程進度：02 / 06 元件與模板本頁語法／概念：三份工作單

一個元件由三份工作單組成：長什麼樣、有什麼資料、看起來如何。

  • 模板（templateUrl）決定結構與要顯示哪些資料。
  • 類別（class）放資料與方法。
  • 樣式（styleUrl）只管外觀。
  • 三份工作單合起來，才是一張看得到的卡片。
HTML模板
<!-- app.html -->
<h1>{{ shopName }}</h1>
<p>{{ price }} 元</p>
CSS樣式
/* app.css */
h1 { font-size: 40px; }
TypeScript資料與方法
@Component({
  selector: 'app-root',
  templateUrl: './app.html',
  styleUrl: './app.css',
})
export class App {}
這頁記住：模板管結構、類別管資料、樣式管外觀。

課程進度：02 / 06 元件與模板本頁語法／概念：插值

雙大括號是「把資料放到這裡」的意思。

16/62

文字與屬性是不同位置

課程進度：02 / 06 元件與模板本頁語法／概念：屬性綁定

文字放雙大括號，元素的「設定」放中括號。

  • [disabled]="soldOut" 控制按鈕能不能按。
  • [src]、[value]、[class.night] 都是同一種寫法。
  • 注意：disabled="false" 還是「有這個屬性」，按鈕照樣禁用。
  • 中括號代表「右邊是資料，不是字串」。
HTML模板
<!-- 屬性：放在標籤裡面 -->
<button [disabled]="soldOut">加點</button>

<!-- 文字：放在標籤中間 -->
<p>{{ soldOut ? '已售完' : '可以點' }}</p>
TypeScript資料與方法
export class App {
  soldOut = true;
}
這頁記住：文字用 {{ }}、屬性用 [ ]、事件用 ( )。

17/62

樣式也能跟著狀態走

課程進度：02 / 06 元件與模板本頁語法／概念：class 綁定

同一個區塊，白天和深夜只是換一組樣式。

  • [class.night]="night()"：條件成立才掛上 night 這個 class。
  • CSS 只負責 .night 的顏色，不管什麼時候該變。
  • 狀態判斷留在程式，樣式留在 CSS，兩邊不要混。
  • 除了顏色，也給文字提示——不能只靠顏色分辨狀態。
HTML模板
<article [class.night]="night()">
  <h1>收店之後的那碗麵</h1>
</article>
CSS樣式
.night {
  background: #232019;
  color: #efe7d6;
}
TypeScript資料與方法
export class App {
  night = signal(false);
}
這頁記住：class 綁定＝用資料決定「掛不掛這個樣式」。

18/62

三種括號配對賽

課程進度：02 / 06 元件與模板本頁語法／概念：三種括號

三種括號各管一件事，配錯就是最常見的錯誤來源。

  • {{ }} 插值：把值變成文字。
  • [ ] 屬性綁定：把值交給元素的設定。
  • ( ) 事件綁定：使用者做了什麼，呼叫哪個方法。
  • 三個一起用：<button [disabled]="count() === 0" (click)="add()">{{ count() }}</button>。

20/62

你指令，我接招

課程進度：03 / 06 事件與 signal本頁語法／概念：事件綁定

21/62

函式是按鈕的動作單

課程進度：03 / 06 事件與 signal本頁語法／概念：方法

方法寫在類別裡，按鈕只是「呼叫它」的開關。

  • add() 寫在 App 類別裡，跟 signal 放在一起。
  • 方法裡讀 signal 要加 this：this.count()。模板裡不用 this。
  • 一個方法只做一件事，名字要說出它做什麼。
  • 按鈕、輸入框、表單都能呼叫同一個方法。
HTML模板
<button (click)="add()">＋</button>
<span class="num">{{ count() }}</span>
TypeScript資料與方法
export class App {
  count = signal(0);

  add() {
    this.count.set(this.count() + 1);
  }
}
這頁記住：方法在 ts、呼叫在 html；ts 裡讀 signal 要加 this。

23/62

一份會通知畫面的資料

課程進度：03 / 06 事件與 signal本頁語法／概念：signal

signal 是一個盒子：裡面裝值，變的時候會通知畫面。

  • count = signal(0)：宣告一個裝 0 的盒子。
  • 要記得 import { signal } from '@angular/core'。
  • 它跟普通變數最大的差別：改值時畫面會知道。
  • 類比取餐號碼牌——號碼一換，螢幕就跟著換。
HTML模板
<span class="num">{{ count() }}</span>
TypeScript資料與方法
import { Component, signal } from '@angular/core';

export class App {
  count = signal(0);
}
這頁記住：signal 是「會通知畫面的資料盒子」。

讀值要打開盒子

盒子不會自己變成數字，要打開它。

這頁記住：讀 signal 一定要加括號：count()。

25/62

寫值用 set

課程進度：03 / 06 事件與 signal本頁語法／概念：set

改值不是 count = 1，而是呼叫 set。

  • this.count.set(1)：直接換成 1。
  • this.count.set(this.count() + 1)：先讀、再加、再寫回。
  • 不能用 count++ 或 count = 1，signal 不會收到通知。
  • set 之後，所有用到 count() 的地方一起更新。
HTML模板
<p>已加 {{ count() }} 份</p>
TypeScript資料與方法
add() {
  // 先讀、再加、再寫回
  this.count.set(this.count() + 1);
}
這頁記住：signal 只有 set（和 update）能改；直接賦值畫面不會動。

CH7 · 26

26/62

重設也是一次更新

課程進度：03 / 06 事件與 signal本頁語法／概念：reset

重設不是「清掉」，而是「再設一次 0」。

  • reset() { this.count.set(0); }。
  • 加三次 → 重設 → 再加一次，結果應該是 1，不是 4。
  • 重設與加點是同一條路：都是改同一個 signal。
  • 按鈕的 disabled 也跟著回到初始狀態。
HTML模板
<button (click)="reset()" [disabled]="count() === 0">
  重設
</button>
TypeScript資料與方法
reset() {
  this.count.set(0);
}
這頁記住：重設就是設回初始值；資料回去，畫面自然回去。

28/62

@if：資料不同，畫面不同

課程進度：03 / 06 事件與 signal本頁語法／概念：@if

有些內容，只有某種狀態下才該出現。

  • @if (isOpen()) { ... }：條件成立才顯示裡面的內容。
  • 不成立時，那段 HTML 根本不存在（不是隱藏）。
  • 適合：營業才顯示的加點入口、有資料才顯示的清單。
  • 不要用 CSS 的 display:none 假裝——資料層面就不該有它。
HTML模板
@if (isOpen()) {
  <p>現在可以加點</p>
}
TypeScript資料與方法
export class App {
  isOpen = signal(true);
}
這頁記住：@if 是「要不要放進畫面」，不是「要不要顯示」。

29/62

@else：替另一種狀態說句話

仿作 Colorfigures：Prompt 怎麼下？

可以直接交給 Coding Agent 的第一版 Prompt
請建立一個「單檔 index.html」的互動等軸 SVG 自動販賣機。

限制：不用 React／Vue／Angular，不用外部繪圖套件；使用原生 HTML、SVG、CSS、JavaScript。

視覺：手繪線稿、暖色紙張背景、固定等軸視角，有正確遮擋與陰影。

互動：投 50 元、選 A1 飲料、開取物門、拿飲料、退幣、取硬幣、搖機器；另有 See-through 與 Labels 切換。

狀態：集中在一個 state 物件，由 render() 統一更新；CSS transition 做動態。

驗收：每一步只能在正確狀態執行；信用額、商品、門與找零狀態都正確；桌機與手機可操作。

預估工作時數

AI + 現成 skill4–8 小時一台完整可玩的物件
從零刻 SVG／互動12–24 小時含投影、狀態、動畫、RWD

工時是假設熟悉前端、AI 輔助，並包含 2–3 輪視覺與互動修正。

仿作 fab24hr：Prompt 怎麼下？

可以直接交給 Coding Agent 的第一版 Prompt
基於 fab24hr-engine，做一個 5–10 分鐘可完成的「半導體夜班工程師」3D 網頁故事。

沿用 engine，不重做移動、對話、存檔與分享系統。

內容：1 個廠區、4 位角色、6 個任務節點、3 個可點術語、1 通電話事件、1 個小遊戲、1 張結局卡。

流程：玩家可用鍵盤／螢幕方向鍵走動，靠近角色對話；next step 能帶路；手機與桌機皆可操作。

技術：維持原生 JavaScript + three.js；使用現有 build／test。

驗收：npm test 通過；桌機與手機各完整走完一次；重開可續玩；結局卡可分享。

預估工作時數

沿用 fab24hr-engine + AI12–24 小時5–10 分鐘可玩章節
完整內容量40–80 小時多角色／多區域／完整故事
連 engine 都從零做120–240+ 小時3D、移動、對話、存檔、分享、RWD

最大差異不是模型能力，而是有沒有沿用現成 engine；重造引擎會讓工時直接跳一個量級。
